# connector-cli Local Login

## Direct Answer

`/connector/local/login` is a local-dev browser handoff for
`connector-cli local login`. It is not the normal **left sidebar > Connectors**
management UI and it is disabled in production.

## What It Is

- `connector-cli local login` is a hidden local-dev command.
- The command prints and opens a login URL such as
  `/connector/local/login?...`.
- The web route is enabled when the web adapter is not `prod`.
- In `prod`, the route redirects away to `/`.
- The CLI waits up to about 10 minutes for the loopback callback by default.
- If the browser user is not signed in, the route starts the normal shared
  sign-in flow and returns to the same local-login URL.
- After sign-in, the page calls the app-server local-login start endpoint and
  redirects to a `127.0.0.1` callback listener owned by connector-cli.

## Required URL Parameters

The browser page expects:

| Parameter | Meaning |
|---|---|
| `client_state` | Opaque nonce generated by connector-cli. |
| `callback_port` | Local callback port where connector-cli is listening. Must be an integer from 1 to 65535. |
| `code_challenge` | PKCE-style SHA-256 challenge derived from the CLI verifier. |
| `code_challenge_method` | Must be `S256`. |

If a required parameter is missing or invalid, the page shows **Local login
failed. Please try again from the terminal.**

## Flow

1. Developer runs `connector-cli local login`.
2. connector-cli chooses `client_state`, `code_verifier`, `code_challenge`, and
   a random `127.0.0.1` callback port.
3. Browser opens `/connector/local/login` with callback and challenge params.
4. If needed, browser completes normal MoClaw login.
5. Browser posts `client_state`, `code_challenge`, and `S256` to
   `/api/connector/start_local_login`.
6. App-server creates a one-time exchange code and stores local runtime config
   for a short TTL.
7. Browser redirects to
   `http://127.0.0.1:<callback_port>/callback?client_state=...&code=...`.
8. connector-cli validates `client_state`.
9. connector-cli exchanges the one-time code and private `code_verifier` through
   `/api/connector/exchange_local_login`.
10. A successful exchange writes local connector runtime config.

## Safety Boundaries

- The browser callback URL carries only `client_state` and the one-time code.
- The browser URL does not carry the sandbox token.
- The CLI, not the browser, exchanges the code with the private verifier.
- The exchange code is one-time and can expire or be consumed.
- The hidden local command can overwrite local connector config.
- The CLI writes the successful runtime config to the local connector config
  path with restricted file permissions.
- Normal support should not expose internal runtime config, sandbox tokens, code
  verifiers, or connector config contents.

## Visible States

| Visible Copy | Meaning |
|---|---|
| `Login is required. Redirecting to login...` | Browser must complete shared MoClaw login first. |
| `Completing local login...` | Browser is requesting the one-time code and redirecting to the local callback. |
| `Local login failed. Please try again from the terminal.` | URL params, auth, start endpoint, callback handoff, or one-time exchange likely failed. |
| `connector-cli local login` | Page title for this local-dev handoff. |

## Recovery Guidance

- Start from the terminal command again instead of hand-editing the local-login
  URL.
- If the route redirects to `/`, the environment is probably production or
  otherwise disabled for local login.
- If login is required, complete normal MoClaw login and let the browser return
  to the local-login URL.
- If the browser shows local-login failure, retry from the terminal so the CLI
  generates a fresh state, verifier, port, and URL.
- If the CLI reports timeout, rerun the command; the documented wait window is
  about 10 minutes.
- If the local callback cannot bind, use the CLI output and local environment to
  diagnose the 127.0.0.1 callback listener.

## Do Not Say

- Do not tell normal users this is where they manage GitHub, Linear, Google, or
  remote MCP servers.
- Do not say this is available in production.
- Do not ask users to paste sandbox tokens, code verifiers, exchange codes,
  connector config files, OAuth tokens, or passwords.
- Do not treat `connector-cli local login` as a public connector installation
  flow.
- Do not confuse this with Local Desktop file/browser permissions.
